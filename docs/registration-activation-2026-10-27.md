# 邮箱格式注册、激活码和加载器 1.0.2

本文为当时交付记录。2026-10-28 的混合续期与 Beta 规则已更新，当前行为见 [分程序续期、Beta 通行证与旧版本删除](entitlements-and-version-deletion.md)。

按照本次确认，邮箱只作为登录账号并检查格式，不发送验证码，也不需要 SMTP 配置。后台创建账号仍支持原有的普通用户名。

## 使用方式

1. 后台打开「激活码管理」，选择数量、授权时长、程序范围、Beta 权限和可选的兑换截止时间。
2. 点击「生成并下载 CSV」。完整激活码仅在这次下载中提供，服务器只保存其 SHA-256 哈希及尾号。下载失败时先检查记录，可作废无法交付的码后重新生成。
3. 加载器登录页点击「注册账户」，填写邮箱、12–128 位密码和激活码。注册成功后开始计算授权时间，再用邮箱和密码登录。
4. 已有账户在程序库点击「兑换激活码」。续费要求程序范围和 Beta 权限一致，从 `max(当前到期时间, 当前服务器时间)` 起增加时长；过期账户也可登录续费。

时长支持 1、7、30、90、365 天和永久。兑换截止时间只限制激活码何时可使用，不是账户最终到期时间。永久账户兑换会被拒绝，避免消耗激活码。完整激活码不在管理列表或审计日志中显示。

自助注册支持常用的非引号邮箱形式，自动去除两端空格、统一小写；不验证邮箱所有权，不支持带斜杠或引号的特殊邮箱形式。新注册密码使用 PBKDF2 哈希保存，不提供原密码查看；后台创建和重置密码的现有流程保持兼容。

## 一次性兑换与恢复

- 激活码使用服务器密码学随机数生成，包含 160 位随机值，格式为 `CSP-` 加 8 组字符。客户端不生成码、不持有生成密钥。
- 注册和续费在服务端同一个锁内验证、修改账号、消费激活码；并发请求只有一个能成功。无效格式、重复邮箱、不匹配权限等失败不会消费激活码。
- `activation-keys.json` 保存哈希、权限、时长、生成时间、兑换期限、使用者和状态。已使用、作废、兑换过期的码不可再兑换。
- `activation-transaction.json` 是先落盘的恢复记录，包含本次完整的用户和激活码快照；两个数据文件写完后移除。服务启动及后续读取会先恢复未完成的记录，避免中断后激活码重新可用。
- 与现有 JSON 存储一样，数据目录应由一个服务进程写入。离线 CLI 修改数据时应停止服务。已有备份脚本包含上述 JSON 文件；恢复时保留恢复记录，不要单独删除它。
- 注册与兑换接口使用现有登录限流及 8 KB 请求体上限；后台生成和作废要求管理员登录及 CSRF 校验。

接口：`POST /api/v1/register` 接收 `email/password/code`；`POST /api/v1/activation/redeem` 接收 `code`，要求有效登录会话，允许订阅过期。旧的登录、账户查询、程序授权接口继续有效。

## 界面修复

- 关闭和最小化按钮移到所有页面共用的固定标题栏，登录、注册、程序库和兑换页都可见。
- 账户名、剩余时间及到期时间独立于右侧操作按钮；长账户名省略显示。
- 倒计时只更新自己的缓冲绘图区域；账户过期状态切换时才更新操作权限。
- 每分钟后台同步不再切换全局忙碌状态。数据相同时保留卡片对象、选择和滚动位置，不重绘操作按钮。
- 忽略退出登录或续费之前发起的陈旧账户响应，避免旧请求覆盖新的账户信息。程序本身的授权心跳频率未改动。
