## 页面

- 概览顶部展示在线用户数、运行实例数、累计上传 / 下载正文流量和两次采样间的平均速率，每 15 秒刷新，也可手动刷新。
- 在线列表展示账号、程序 / 版本、来源 IP、启动时间和最近心跳。只有有效租约且两个心跳周期加 15 秒内有活动的程序计入在线；同一账号运行多个实例只计一个在线用户。单纯登录加载器不算程序在线。退出、授权撤销、版本禁用或心跳超时会从列表移除。
- 流量按服务器视角统计实际读入 / 写出的 HTTP 正文，含管理后台、上传分块及下载 Range；不包含头部、TLS、其他进程。统计随服务重启清零，不能当作云厂商账单或已被客户端确认接收的网络字节数。
- 账号支持搜索、程序、授权状态、程序在线筛选，每页 20 个。到期、权限、密码和删除操作分别折叠，密码原有二次验证保持有效。
- 激活码按“程序范围 → 时长”两级展开，显示可用数 / 总数；同名不同 ID 的程序范围保持独立。完整卡密仍只在生成时下载一次。

## 计费

每个稳定程序展开后提供“暂停计费 / 恢复计费”和“补偿时间”按钮。Beta 使用所属稳定程序的计费状态。

- 暂停保持程序可用，冻结剩余授权时间；恢复继续计时。暂停和恢复都是设置目标状态，重复提交不会重复补时。暂停状态持久化，停服时间也纳入暂停区间。
- 补偿单位为分钟，允许 1–525600 分钟，每次只增加目标程序当前有效的限时授权。永久、已到期和未授权账号不受影响；页面反馈实际更新账号数。补偿属于累加操作，再次确认执行会再次增加时间。
- 暂停期间新增授权、续费、管理员设置到期时间和补偿均使用当前计时基准，避免把授权产生前的暂停时间重复算进去。
- 新增管理动作均要求管理员会话和 CSRF，成功操作记录到现有 `admin-audit.log`，包括补偿分钟数及账号数。

程序 `program.json` 保存 `billingPausedAt` 和累计 `billingPausedTicks`；账号 `billingOffsets` 保存最近一次到期时间写入时的基准。对外授权截止时间由原始到期时间加计费偏移差计算，API、下载、启动票据和心跳统一使用有效截止时间。旧数据缺少这些字段时以零偏移读取，不需预先批量迁移。原始 `users.json` 的到期时间不一定等于 API 当前展示的截止时间；备份应完整保留用户和程序数据，旧版服务端不会解释计费偏移字段。
