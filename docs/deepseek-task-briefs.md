### 修改和验证边界

- 只实现本次任务，保留无关界面和功能；不要顺手重写架构。

- 关注服务端先升级、客户端后分发的兼容顺序；涉及协议变更必须写明迁移方法。

## 任务 01：固定正式发布地址，防止重新打包后失联

**目标**：双击正式发布入口时，可靠生成指向正式 HTTPS 地址的客户端。

**当前问题**：`publish-client.ps1` 的默认参数仍为 `http://127.0.0.1:5115`，`PUBLISH-CLIENT.cmd` 没有传地址。当前已发布 EXE 正确，不代表以后重新打包也正确。

**修改范围**：优先检查 `publish-client.ps1`、`PUBLISH-CLIENT.cmd`、`client/Chispa.Launcher.csproj` 和 README。

**实施要求**：

- 建立可重复使用的正式发布配置，保存上述正式地址。
- 明确区分本机测试和正式发布。正式发布拒绝回环地址、远程 HTTP、无效端口及带路径的错误地址；保留显式本地开发方式。
- 打包后检查实际产物中的服务器地址，不能只打印命令传入值。单文件可能压缩，不能将简单字符串搜索作为唯一验证。
- 构建到暂存目录，验证成功后再替换分发目录中的产物，失败时保留原可用版本。

**验收**：默认正式入口使用正确地址；错误配置明确失败；本地开发仍可用；构建失败不破坏上一版。附真实打包和产物地址验证结果。

## 任务 02：主程序内部授权，补齐绕开加载器的路径

**目标**：用户直接打开下载出的主程序时，也执行授权检查。

**当前问题**：加载器已有在线启动验证，但只改加载器无法约束独立 EXE。主程序源码不在当前 loader 仓库，本简报尚未审查它的现有授权机制。

**修改范围**：先定位并确认实际主程序源码及启动入口；预期相关目录为相邻的 `D:\desktoop\wardogs chispa`。读取该仓库指引。仅修改授权相关入口和 loader 配套接口，不改其他业务功能。

**实施要求**：

- 先检查主程序是否已接入授权，列明真正缺失部分。拿不到主程序源码时，明确阻塞点，不能用加载器校验代替完成。
- 设计短时启动凭证或等效方案，绑定账号和程序；由服务端重新检查期限、权限和撤销状态。
- 明确直接启动、重复使用凭证、退出登录、账号过期、断网及运行中撤销的行为。默认新启动需要在线校验；运行中是否定期验证及断线宽限需明确产品规则。
- 不在命令行参数、普通日志或明文文件中传递长期密码、长期令牌；签名私钥不得放在客户端。
- 检查客户端与服务端兼容顺序，说明旧版本仍可能绕开新流程的限制和处置方式。

**验收**：模拟程序或可安全执行的授权测试入口覆盖直接启动、有效凭证、错误程序、过期凭证、重放、授权撤销、网络失败。说明修改后的正常授权流程以及本地可执行程序仍可被有能力者修改的边界。

## 任务 03：给发布清单签名并在客户端验签

**目标**：即使下载服务器上的包和普通 SHA-256 清单一起被替换，客户端仍能拒绝未获信任签名的内容。

**修改范围**：检查 `server/Program.cs` 的发布与清单逻辑、`client/LauncherApi.cs`、`client/Installer.cs`，增加必要的签名工具。

**实施要求**：

- 使用成熟密码库的标准非对称签名，不自创算法。
- 明确签名覆盖的原始字节和格式版本，覆盖程序 ID、版本、入口文件、包大小和哈希等安全相关字段，避免 JSON 重序列化造成歧义。
- 客户端内置可信公钥，支持密钥标识和后续轮换；未知密钥、无签名或签名错误必须按明确策略拒绝。
- 私钥保存在独立发布环境，不放在公开下载服务、源码或分发包中。
- 网页上传必须兼容这一信任模型，例如上传已签名的发布材料；不能让被攻陷的下载服务随意给任意包补签。
- 保留现有下载大小和 SHA-256 检查，设计旧发布包签名迁移及旧客户端处置流程。

**验收**：合法包可安装；修改包、修改清单字段、替换程序 ID、未知密钥和缺失签名均有预期结果；历史版本迁移有可执行说明。测试使用专用临时密钥。

## 任务 04：服务与隧道恢复，以及代理安全配置

**目标**：保留当前可用公网地址，使服务和隧道故障后能恢复，并验证代理后的安全行为。

**当前问题**：历史公网探测成功，但没有完成长期运行保障验收；源码尚未见明确可信代理处理，管理 Cookie 使用 `SameAsRequest`。

**实施要求**：

- 先只读识别现有服务、隧道运行方式和 TLS 终止位置，不假设必须重建部署。
- 为现有架构补服务开机自启、崩溃恢复、隧道重连的配置或安装脚本；如果现有配置已具备，给出验证证据，避免重复安装。
- 只信任已配置代理的协议和来源 IP 信息，不能接受任意客户端伪造转发头。
- 生产管理 Cookie 设置 Secure，保留 HttpOnly、SameSite 和 CSRF 保护，并保持显式本机开发方式可用。
- 提供不泄露内部信息的就绪检查；补日志轮转和可用性检查方案。告警目的地不明时做成配置项，不自行发送消息。
- 交付重启、断网重连、进程退出和恢复验证步骤；先在隔离环境验证，正式停机测试另行安排。

**验收**：伪造转发头不能改变信任判断；生产 Cookie 标记正确；真实来源识别与限流匹配；有自动恢复验证记录或清楚列明待执行的正式环境步骤。

## 任务 05：自动备份及可验证恢复

**目标**：账号、权限、发布包及密钥损坏时，有明确可用的恢复路径。

**实施要求**：

- 提供备份和恢复脚本，覆盖必要数据及密钥，配置异地或独立磁盘目标和保留策略；不要擅自上传到外部服务。
- 处理正在写入、发布或删除程序时的一致性，不能只复制一批可能不匹配的文件。
- 备份包含可解密密码及密钥，需限制访问并防止敏感内容进入日志或仓库。
- 检查 Windows DPAPI 绑定服务身份/机器的实际行为。不能宣称复制 `keys` 文件夹就必然能异机恢复；若迁移需要额外机制，提供明确方案。
- 恢复默认写入新目录，验证后再切换；防止错误路径覆盖或删除现有数据。
- 使用临时账号和测试包做真实恢复演练，记录备份频率、最大可能数据损失和预计恢复步骤。

**验收**：隔离环境恢复后能登录、读取正确权限并下载校验通过的测试包；损坏备份会报错；正式数据未受影响；区分同机与异机恢复的已验证范围。

## 任务 06：保留查看密码功能，并加固后台

**目标**：尊重当前“管理员能查看用户密码”的要求，降低后台失守与误操作风险。

**修改范围**：重点检查 `server/AdminPages.cs`、密码解密接口、管理身份验证及日志实现。

**实施要求**：

- 不擅自删除密码查看功能，不将现有密文转成明文保存。
- 查看密码前要求重新验证管理员身份，使用短时且服务端验证的授权；不能只加浏览器弹窗。
- 对重新验证和查看操作限流，保留 CSRF、身份权限检查和禁止缓存。
- 记录谁在何时查看了哪个账号的密码及结果，绝不记录密码、凭证或响应正文。
- 限制敏感页面显示时间，刷新/退出后不保留内容；说明浏览器截图及已显示内容无法技术性收回。
- 提供可配置的后台访问限制，并避免锁死现有管理员；解释密钥访问控制和管理员账户恢复办法。

**验收**：未登录、缺少二次验证、验证过期、CSRF 失败均不能查看；有效管理员可按原需求查看；审计可追溯且不含秘密；失败尝试触发限流。

## 任务 07：版本推荐、撤回与加载器升级提示

**目标**：发布错误版本后可以快速恢复；用户知道加载器自身需要更新。

**当前问题**：最新版本按最大版本号决定，缺少明确推荐/禁用状态；主程序更新与加载器自身升级是两件事。

**实施要求**：

- 为每个程序增加推荐版本和版本状态，后台支持切换推荐、撤回分发和禁止通过加载器启动指定版本。
- 明确“撤回下载”和“禁止启动”的区别；授权检查、最新版本、下载和启动接口采用一致规则。
- 推荐版本回退不得自动破坏用户配置，保留恢复办法；迁移旧版本数据时维持合理默认行为。
- 增加加载器版本信息、新版提示和可配置下载入口。首版可由用户手动下载，不强求复杂自更新。
- 如果支持最低加载器版本，服务端必须验证实际协议能力，不能只依赖容易伪造的版本字符串来作为安全边界。
- 与任务 03 签名方案兼容；未完成主程序内部授权时，不声称禁用状态可以阻止直接打开旧 EXE。

**验收**：模拟新版本故障后，后台能切回旧推荐版本；禁用版本被相应接口拒绝；其他程序不受影响；新版本提示不影响正常登录且错误入口不会自动执行文件。

## 任务 08：下载恢复、限流及故障回归

**目标**：正常用户遇到慢网、下载中断或磁盘问题时有清楚反馈；异常请求不轻易拖垮服务。

**实施要求**：

- 客户端增加有界重试、可取消操作、磁盘空间检查和明确错误信息。认证失败、权限撤销和签名错误不能无限重试或绕过。
- 若实施断点续传，验证 Range、版本一致性与断点文件，恢复完成后仍进行完整大小、哈希和签名校验；未实现则如实说明。
- 处理文件占用、重复运行加载器和安装中断，避免两个安装任务写同一个目录；保留原可用版本及用户配置。
- 为登录、普通 API 和上传接口分别设置合理请求大小、输入长度、速率和并发上限。
- 给过期会话和登录失败记录增加有界清理；检查全局锁中的高成本计算，减少对正常请求的阻塞。
- 补关键故障回归和可重复执行的验证入口，使用假程序和独立数据目录。不向当前公网服务进行未经安排的压力测试。

**验收**：覆盖下载中断/取消、服务端重启、磁盘不足、包损坏、文件占用、并发安装、权限撤销和过期记录清理；报告测试规模、耗时、失败数及测试环境，不给未经实测的并发容量承诺。
